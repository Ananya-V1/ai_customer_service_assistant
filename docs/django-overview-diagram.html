The four pieces that handle a request

Routing, logic, data, and shape — each request passes through all four in order.

urls.pyrouting

Matches an incoming URL to a view. Nothing more — no logic lives here.

path("chat/", ChatView.as_view())
router.register("documents", DocumentViewSet)

Why: keeps "which code runs for this path" in one readable list, separate from the code itself.

views.pylogic

Decides what happens for a request — reads input, calls into models/services, builds a response.

class ChatView(APIView):
    def post(self, request):
        ...

Why: the one place request-specific decisions get made — everything else is reusable plumbing.

models.pydata

Python classes that map 1:1 to database tables — this is Django's ORM (object-relational mapper).

class KnowledgeBase(models.Model):
    name = models.CharField(max_length=255)

Why: you query and save data with normal Python, never hand-writing SQL.

serializers.pyshape

Converts between a model instance and JSON, in both directions, with validation on the way in.

class DocumentSerializer(ModelSerializer):
    class Meta:
        model = Document

Why: the JSON contract for the API lives in one place, decoupled from the DB schema.

Setup-time, not per-request
Three more pieces, all built from your models

None of these run while handling a live request — they generate tooling and configuration ahead of time.

admin.pyfree UI

A CRUD web page auto-built from a model's fields — no HTML written by hand.

@admin.register(KnowledgeBase)
class KnowledgeBaseAdmin(ModelAdmin):
    list_display = ("name", "slug")

Why: instant internal tooling for staff, for free, from code you already wrote.

migrations/schema history

Generated by diffing your models against the last-known schema — one file per change.

migrations.CreateModel(
    name="KnowledgeBase", fields=[...])

Why: every environment (yours, CI, prod) replays the same steps and ends up identical.

settings.pythe glue

Central config: database connection, installed apps, middleware — wires the other six together.

DATABASES = {"default": {
    "ENGINE": "django.db.backends.postgresql"}}

Why: one file to change environments (local vs. Docker vs. prod) without touching app code.
